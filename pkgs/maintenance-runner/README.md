# maintenance-runner

Rust coordinator for the fixed `prepare → capture → archive → maintain_storage
→ resume` lifecycle. It suspends declared writers after capture, before archive.
The contracts, NixOS registration API, Borg integration, operating procedures
and recovery model are documented in [docs/maintenance.md](../../docs/maintenance.md).

The JSON configuration is an internal interface generated by the NixOS module;
configure `homelab.maintenance` rather than maintaining it manually. All hooks
run synchronously under the coordinator, with separate process groups and
inherited session-lock descriptors. Application data is opaque to the runner.

```sh
cargo test --manifest-path pkgs/maintenance-runner/Cargo.toml
cargo clippy --manifest-path pkgs/maintenance-runner/Cargo.toml --all-targets -- -D warnings
```

The binary supports `run --config FILE`, `recover --config FILE`,
`check-storage STATE_DIR`, `remember KEY JSON` and `publish TEMP_NAME FINAL_NAME`.
The last two operate inside the current participant's supplied directories.
Production invocations use the systemd services; native non-Linux builds support
development tests only.
